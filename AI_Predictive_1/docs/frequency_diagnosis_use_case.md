# Use Case 3 — Frequency-Based Fault Diagnosis

## Purpose

The first two use cases monitor daily sensor readings and forecast future telemetry/condition. This third use case analyses vibration frequency content to identify patterns consistent with:

1. Rotor imbalance — a dominant radial 1x running-speed component.
2. Shaft misalignment — a relatively strong 2x component, with axial vibration as supporting evidence.
3. High-frequency vibration plus high temperature — high-frequency spectral energy and a simultaneous temperature elevation.

## Data flow

1. Select machine and date from the existing telemetry view.
2. Choose either the synthetic event schedule for that machine/date or a controlled synthetic test case.
3. Generate a labelled synthetic time waveform for each sensor location and direction (P1–P4, H/V/A) for demonstration purposes.
4. Compute the FFT RMS spectrum and extract 1x, 2x, 3x and high-frequency features.
5. Apply transparent heuristic rules and display the diagnostic candidate, supporting features, selected sensor spectrum and a 12-channel summary.

## Important limitations

- Daily overall vibration values cannot be inverted to obtain a real FFT spectrum. Real diagnosis requires a waveform or measured spectrum linked to the machine, location, direction and timestamp.
- The waveforms generated by this module are synthetic and are labelled `SYNTHETIC_SIMULATION`.
- Rule thresholds in `frequency_diagnosis.py` are demonstration heuristics, not ISO thresholds and not calibrated fault probabilities.
- ISO vibration zone limits apply to suitable overall vibration measurements and must not be applied directly to individual 1x/2x/3x spectral amplitudes.
- A 1x peak or 2x peak alone does not prove a fault. Confirm diagnosis using phase, operating speed/load, physical inspection and other relevant measurements.
- The high-frequency/high-temperature condition requires both elevated high-frequency spectral energy and elevated temperature.
- This academic prototype must not actuate machinery or replace certified protection systems.

## Running

```bash
pip install -r requirements.txt
streamlit run app.py
```

Open **Date-to-Date Report, Trends & Frequency Analysis** and scroll to **Use Case 3 — Frequency-Based Fault Diagnosis**. Select a machine/date and choose either the event schedule or a controlled synthetic scenario. Change location and direction to compare sensor responses.
